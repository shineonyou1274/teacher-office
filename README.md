# AI 교무실

수업 준비를 여러 팀으로 쪼개 AI에게 맡기고, **선생님은 하루에 한 번만 결정합니다.**
기본은 12개 팀이고, 3~12개 사이에서 마음대로 줄이거나 늘릴 수 있습니다.

혼자 다 하지 말고, 역할을 쪼개서 맡겨보자는 도구입니다.
설치하면 바로 돌아갑니다. **연동도, API 키도 필요 없습니다.**

**→ [설치 없이 먼저 보기](https://shineonyou1274.github.io/teacher-office/)** · 링크만 누르면 화면이 열립니다

---

## 1. 실행하기 (10분)

**필요한 것**: Node.js 18 이상 ([nodejs.org](https://nodejs.org)에서 설치)

**검은 창(PowerShell·터미널)에 한 줄씩** 칩니다. 설명을 같이 붙이지 마세요.

```bash
git clone https://github.com/shineonyou1274/teacher-office
cd teacher-office
npm install
npm run setup
npm run dev
```

`cd teacher-office` 를 빼먹으면 `package.json` 을 못 찾는다는 오류가 납니다.
다음에 다시 열 때도 **먼저 그 폴더로 들어가야** 합니다.

**전에 받아두신 게 있다면** 새로 받지 마시고 최신으로 당겨 오시면 됩니다.

```bash
cd teacher-office
git pull
npm install
```

`Missing script` 오류는 대개 이 경우입니다 — 그 명령이 만들어지기 전에 받으신 것입니다.

**`git pull` 이 `Aborting` 으로 멈추면** 전에 설정 파일을 고치신 것입니다.
고친 내용을 잠시 치워두고 당겨 오면 됩니다.

```bash
git stash
git pull
npm install
```

`git stash` 는 **지우는 게 아니라 치워두는** 것입니다. 치워둔 내용은
`git stash show -p` 로 볼 수 있습니다. `npm run setup` 이 어차피 학교명과
이름을 다시 물어보니, 대개는 그걸로 새로 채우시면 됩니다.

`npm run setup` 은 **설치 인터뷰**입니다. 두 부분으로 나뉩니다.

- **이름표** (학교·성함·호칭·과목) — 답이 정해져 있어 이 창에서 바로 고칩니다.
- **하는 일과 AI 쓰면서 걸린 것** — 떠오르는 대로 여러 줄 적으시면 됩니다. 정리는 안 합니다.
  받아 적은 그대로 `MY_ANSWERS.md` 로 남기고, 그다음은 `SETUP.md` 를 AI에게 읽혀서 이어갑니다.
  AI가 "제가 이해한 순서는 이렇습니다 — 맞나요?" 하고 되물어보며 정리합니다.

**팀이 이미 선생님 일에 맞게 짜여 있으면 이름표만 묻습니다.** 하는 일과 불만을
묻는 건 팀을 짜기 위해서인데, 이미 짜여 있으면 물을 이유가 없으니까요.
적어두신 `MY_ANSWERS.md` 도 건드리지 않습니다. 이름표만 고치고 싶을 때는
언제든 `npm run setup -- --이름표만` 입니다.

건너뛰어도 됩니다 — `school.config.ts` 를 직접 고쳐도 같습니다.
(원본은 `.bak` 으로 남습니다. 되돌리려면 이름에서 `.bak` 만 지우세요.)

브라우저에서 **http://localhost:5180** 을 엽니다.
화면 위 **"오늘 업무 시작"** 을 누르면 31명이 출근합니다.

> 윈도우 PowerShell에서는 `&&` 를 못 씁니다. 한 줄씩 따로 실행하세요.
> 창에서 `Ctrl + C` 를 누르면 서버가 꺼집니다.

## 2. 내 교무실로 바꾸기

세 가지 길이 있습니다. 위에서부터 쉬운 순서입니다.

| 방법 | 무엇을 바꾸나 | 언제 |
|---|---|---|
| `npm run setup` | 이름표 + 하는 일을 받아 적기 | 처음 받았을 때 |
| `SETUP.md` + `MY_ANSWERS.md` 를 AI에게 | **순서 정리 · 팀 다시 짜기 · 금칙어 뽑기** | setup 바로 다음 |
| `school.config.ts` 직접 고치기 | 전부 | 손에 익었을 때 |

두 번째가 핵심입니다. 12개 팀은 제 수업 순서로 짜여 있어서, 과목이 다르면
그대로는 안 맞습니다. 그런데 "선생님 수업 순서를 적어주세요"라고 물으면
대부분 못 적습니다 — 자기 일의 순서는 한 번에 안 떠오릅니다.

그래서 `npm run setup` 은 **정리를 요구하지 않습니다.** "요즘 자주 하는 일이
뭔가요", "그 일을 어떤 식으로 하세요" 정도만 묻고 적은 대로 저장합니다.
정리는 `SETUP.md` 를 읽은 AI가 합니다 — 답을 순서로 묶어 보여주고
"맞나요? 빠진 게 있나요?" 하고 되물은 다음, 확인받은 순서로 팀을 짭니다.

**어느 길이든 결국 고치는 건 `school.config.ts` 한 파일입니다.**

### 채워진 예시부터 보세요

빈칸을 채우는 것보다 남이 채운 걸 고치는 게 쉽습니다.
`examples/studio.config.ts` 는 **실제로 쓰는 하루를 그대로 옮긴 설정**입니다.

```
내 드라이브에서 찾기 → 웹에서 보태기 → 1차 추리기(사람) → AI와 기획 조정
  → ★ 흐름안 고르기 → 연수 자료 → 코딩 → 영상 스토리 → 자동 생성
  → 오늘 연재분 → 검수 → 반응 기록
```

여기서 눈여겨볼 곳이 넷입니다.

- **웹을 뒤지기 전에 내 드라이브부터** 봅니다. 이미 만든 걸 두 번 만들지 않으려고요.
- **1차 추리기는 사람이** 합니다. AI가 먼저 거르지 않습니다.
- **영상은 스토리까지 같이 짜고**, 그 뒤는 자동 생성에 넘겨 **매일 한 화씩** 연재합니다.
  몰아 올리지 않는 게 연재라서요. 올리는 것 자체는 사람이 합니다.
- **아직 연결 안 된 것은 `PENDING`** 에 둡니다. 코딩은 그날그날이고 생성 도구는
  아직 연동 전이라 '자료 대기'로 떠 있습니다. 가짜로 일하는 척하지 않습니다.

쓰시려면 한 줄이면 됩니다.

```bash
npm run use              # 지금 뭘 쓰는지, 고를 수 있는 게 뭔지
npm run use -- studio    # 바꿔 끼우기
npm run use -- 되돌리기   # 직전 것으로 (한 번 더 치면 다시 돌아옵니다)
```

바꿔 껴도 **`npm run setup` 에서 적으신 이름표는 그대로 따라옵니다** —
학교 이름, 배지, 성함, 호칭, 과목 다섯 개입니다. 예시의 이름까지 통째로
쓰시려면 뒤에 `--통째로` 를 붙이세요.

쓰면서 고치려면 설정을 자주 바꿔 끼우게 됩니다. 바꾸기 전 것은
`school.config.ts.bak` 에 남으니 마음 놓고 바꿔 보셔도 됩니다.

### 이름만 바꾸면 남의 교무실입니다

`DEPARTMENTS` 는 "누가 있나"이고, `DAY_PLAN` 은 **"무엇을 먼저 하나"**입니다.
팀 이름만 우리 과목으로 바꾸고 순서를 그대로 두면, 화면은 여전히 만든 사람의
하루를 돕니다. 자료조사 → 학습자 분석 → 아이디어 → 검수 순서로요.

**부서 개수도 12개일 필요가 없습니다.** 3개부터 12개까지 자유입니다.
안 쓰는 부서는 지우세요 — 6개 이하면 교실이 한 줄로 서고 지도가 그만큼
짧아집니다. 2주 동안 한 번도 안 부른 부서는 지우는 편이 낫습니다.

`DAY_PLAN` 의 줄 순서가 곧 하루 순서입니다. 줄을 옮기면 화면이 따라갑니다.
안 하는 단계는 줄을 지우고, 더 하는 일은 줄을 넣으세요. `kind: "결재"` 줄을
선생님이 실제로 고르는 자리에 놓으면, 거기서 화면이 멈춥니다.

| 고칠 것 | 어디 |
|---|---|
| 학교 이름, 화면 제목 | `SCHOOL` |
| 내 이름·호칭·담당 과목 | `TEACHER` |
| **하루 순서 (제일 중요)** | **`DAY_PLAN`** |
| 부서 개수 (3~12개, 자유) | `DEPARTMENTS` |
| 직원 이름·성격·말버릇 | `STAFF` |
| 자료가 없어 멈춘 팀 | `PENDING` |
| 화면 아래 내 크레딧 | `CREDITS` |

저장하면 화면이 바로 새로고침됩니다.

### ⚠️ 딱 2가지만 지키세요

1. **부서 `id` 는 그냥 두시는 게 편합니다** (`research`, `design`, `review` …)
   화면에 뜨는 건 `name` 이라, id는 그대로 두고 이름만 바꿔도 선생님 말로 나옵니다.
   **지우는 건 됩니다** — 안 쓰는 부서는 통째로 지우세요.
   id 까지 바꾸시려면 **세 군데를 같이** — `DEPARTMENTS` 의 `id`, `STAFF` 의 `deptId`,
   `DAY_PLAN` 의 `team`. 하나라도 빠지면 화면 위에 어느 id가 어긋났는지 뜹니다.
   (`examples/studio.config.ts` 가 id까지 바꾼 예입니다.)

2. **부서 개수는 3~12개 사이로.** 교실이 한 줄에 6칸씩 두 줄이라 13개부터는 화면에 안 나옵니다.

직원 수는 자유입니다. 단 **한 팀에 팀장(`rank: "lead"`)은 1명**.

> 설정이 어긋나면 화면에 **무엇이 잘못됐는지 한국어로** 띄웁니다.
> 조용히 깨지지 않으니 안심하고 고치세요.

## 3. 하루가 이렇게 돌아갑니다

```
08:00  전원 출근
  ↓    자료조사 → 학습자 분석 → 수업 아이디어 10개 → 교육과정 검수
  ↓    수업안 3개로 좁히기
🙋 선생님  ★ 여기서 딱 한 번 결정 ★   ← AI가 진짜로 멈춥니다
  ↓    활동지 집필 → 수업자료·학습지 제작 → 평가 문항 → 관찰 기록
  ↓    가정통신 초안 → 성찰 기록
16:4x  교무 비서실이 교무실로 걸어와 브리핑
```

**⑦번이 이 구조의 심장입니다.** 멈추게 하지 않으면 AI는 끝까지 혼자 달려서
활동지까지 다 만들어버립니다. 그럼 내 수업이 아니라 AI 수업이죠.

## 4. 선생님 지시창

화면 오른쪽에서 직접 물어볼 수 있습니다.

| 물어보면 | 답하는 사람 |
|---|---|
| "어디까지 됐어?" | 교무 비서실장 |
| "막힌 데 있어?" | 비서실장이 **병목 하나**를 짚어서 |
| "검수팀 상황" | 그 팀 팀장이 팀원 현황까지 |
| "자리 지키기" | 전원 자리로 복귀 |

답변마다 **출처 배지**가 붙습니다.

- `규칙` — 화면의 실제 상태를 읽어 만든 답 (즉답·무료)
- `안내` — 시스템 안내

> 이 배지가 있어서 **어디까지가 실제 상태인지** 헷갈리지 않습니다.

## 5. 기계 검사 — AI 말을 믿지 않는 층

```bash
npm run check -- 내자료.md --기준 B
```

AI에게 "금칙어 검사해"라고 시키고 "0건입니다"를 믿으면 그건 검수가 아닙니다.
모델은 자기가 방금 쓴 글을 관대하게 봅니다. 그래서 **증명할 수 있는 것은 코드가 직접 찾습니다.**

| 코드가 찾는 것 | 코드가 못 하는 것 |
|---|---|
| 금칙어 (문자열 그대로) | "메시지가 2개인가" |
| 미완성 표시 `[입력 필요]` `(※` | "정답이 보이는 선지인가" |
| 미래형 성과 `산출한다` `보완한다` | "한 문항에서 두 가지를 묻는가" |
| 시간 배분 `○분` 누락 | "바로 해볼 수 있는 게 있는가" |
| 학생용 파일에 정답이 섞였는지 | 식별 가능 정보 |

왼쪽에서 하나라도 걸리면 **반려**입니다. AI가 통과라고 해도 반려입니다.
오른쪽은 "읽어봐야 하는 것"으로 자리를 짚어주고, 판단은 사람이나 AI가 합니다.

금칙어 목록은 `TEACHER_OFFICE.md` 의 표에서 읽습니다. 두 군데에 적지 않습니다.

### 연재 대기열

매일 조금씩 올리는 연재라면 대기열을 파일로 두는 편이 낫습니다.

```bash
npm run serial -- 추가 "검수팀이 반려하는 장면"
npm run serial -- 오늘     # 하나 꺼낸다. 하루에 하나만
npm run serial -- 올림     # 선생님이 실제로 올리신 뒤에
```

대기열이 2개 미만이면 화면과 터미널 양쪽에서 **곧 빈다고 알립니다.**
연재가 끊기는 건 대개 올릴 게 떨어져서라서요.

이 도구는 **아무것도 올리지 않습니다.** 준비까지만 하고, 올리는 건 선생님이 하십니다.
기록은 `serial.json` 에 남고 저장소에 올라가지 않습니다.

### 화면에서 일 시키기

지시창은 원래 각본만 읽었습니다. **"어디까지 됐어?"** 같은 건 지금도 각본이 답합니다 —
화면이 아는 것이니까요. 그런데 **"초등 2회차 자료 만들어줘"** 처럼 일을 시키는 말은
화면이 할 수 없습니다. 그래서 받아 적기만 하고 Claude Code 로 넘깁니다.

```
화면 지시창  →  public/orders.json  →  Claude Code 의 /지시받기  →  public/state.json  →  화면
```

- 화면에서 일을 시키면 **`지시 접수`** 표가 붙습니다. 그 표가 붙은 줄만 넘어간 것입니다
- Claude Code 에서 `/지시받기` 를 치면 꺼내서 실제로 합니다
- 끝나면 그 팀이 화면에서 `마침` 으로 바뀝니다

터미널에서 직접 보셔도 됩니다.

```bash
npm run orders                              # 안 한 지시
npm run orders -- 완료 <id> "<한 줄>"        # 끝낸 것으로 적기
```

**`npm run dev` 로 연 화면에서만 됩니다.** 빌드해서 올린 주소(GitHub Pages 등)에는
받아 적을 데가 없습니다. 그럴 때는 화면이 "여기서는 받아 적을 수가 없어요" 라고
그대로 말합니다 — 적히지도 않았는데 적혔다고 하지 않습니다.

### 화면이 진짜 상태를 읽게 하기

검사를 돌리면 `public/state.json` 에 결과가 쌓입니다. 화면은 이 파일이 있으면
**각본 대신 그 기록을 믿습니다.**

- 부서 현황에 `기록` 배지가 붙고, 상태가 실제 검사 결과로 바뀝니다
- 화면 위에 띠가 뜨고 마지막 결과가 한 줄로 보입니다 (5초마다 새로 읽습니다)
- 파일이 없으면 지금까지처럼 각본만 돕니다. 없는 게 기본값입니다

손으로 한 줄 적어 넣어 보실 수도 있습니다.

```bash
npm run record drive 마침 "작년 연수 자료 4건 꺼냄"
```

상태는 `마침` · `작업 중` · `결재 대기` · `자료 대기` · `대기` 다섯 가지입니다.
팀id는 `school.config.ts` 의 `DEPARTMENTS` 에 적힌 것이고, 없는 팀을 적으면
적지 않고 알려줍니다 — 화면에 안 뜨는 기록을 쌓지 않으려고요.

이 파일은 선생님 컴퓨터의 작업 기록이라 저장소에 올라가지 않습니다.

### 인터넷 주소로 올리기 (선택)

화면만 따로 올려서 링크로 보여줄 수 있습니다. 설치 없이 열리니, 동료에게
먼저 구경시키고 마음에 들면 내려받게 하는 흐름이 됩니다.

1. `main` 에 밀면 `.github/workflows/pages.yml` 이 알아서 올립니다
2. 몇 분 뒤 `https://<내아이디>.github.io/teacher-office/` 가 열립니다

**빈 화면이 뜨면** 저장소 **Settings → Pages → Source** 를 보세요.
`Deploy from a branch` 로 되어 있으면 저장소 폴더를 그대로 올리는 것이라,
개발용 `index.html` 이 떠서 아무것도 안 보입니다. **`GitHub Actions`** 로 바꾸면 됩니다.

올라가는 건 **화면뿐**입니다. 검사 기록은 각자 컴퓨터에만 있으므로 인터넷에
올라간 화면은 각본만 돕니다. 학교 이름도 저장소에 들어 있는 값으로 뜨니,
개인 정보를 넣어 두셨다면 올리기 전에 확인하세요.

### Claude Code로 쓰실 때

이 저장소에는 `.claude/` 가 들어 있습니다. Claude Code를 쓰시면 API 키 없이 그대로 돌아갑니다.

> ⚠️ **아래 `/` 로 시작하는 것은 검은 창(PowerShell·터미널)에 치는 게 아닙니다.**
> **Claude Code 안에서** 칩니다. 검은 창에 치면 "용어가 인식되지 않습니다" 가 뜹니다.
>
> | 어디에 | 무엇을 |
> |---|---|
> | 검은 창 (PowerShell·터미널) | `npm run ...` · `node scripts/...` · `git ...` |
> | Claude Code 안 | `/검수` · `/자료찾기` · `/연재` |
>
> 그리고 **명령어 줄에는 설명을 같이 붙이지 마세요.** 한 줄에 명령어 하나만 칩니다.

- `/검수 내자료.md B` — 사규를 읽고, 기계 검사를 돌리고, 그 결과를 자기 판단보다 우선해서 답합니다. 결과는 화면에도 바로 뜹니다
- `/자료찾기 <찾을 것>` — **내 드라이브를 먼저** 보고(`gws`), 모자라면 웹을 봅니다.
  `gws` 가 없으면 '자료 대기'로 적습니다. 못 본 것을 봤다고 적지 않습니다
- `/자료찾기`·`/연재` 는 **필요한 분만** 쓰시면 됩니다. 기본 설정에는 그 팀이 없어서
  일은 되지만 화면에는 안 뜹니다 (그럴 때 그렇다고 알려줍니다).
  화면에도 띄우시려면 그 팀을 만들고 `--팀 <id>` 로 지정하시면 됩니다
- `/연재` — 오늘 올릴 한 화를 꺼내 준비합니다. **하루에 한 화**만 꺼내고,
  대기열이 비어가면 다음 화를 짭니다. **올리는 건 선생님이** 하십니다
- 어떤 명령이든 결과를 화면에 알릴 수 있습니다 —
  `npm run record <팀id> <상태> "<한 줄>"` (상태는 다섯 가지뿐입니다)
- 교무실 스킬 — "검수팀 기준 B로 봐줘" 처럼 말해도 알아서 이 순서를 따릅니다

```bash
claude -p "/검수 내자료.md B"     # 창을 안 열고 한 번에. cron 에 걸어도 됩니다
```

## 6. 화면 속 직원이 진짜로 일하는 건 아닙니다

솔직하게 말씀드립니다. **이 교무실은 시뮬레이션입니다.**

- 직원들이 걸어다니고 회의하는 건 **정해진 각본**입니다
- "3개로 좁혔다"는 내용은 실제로 만들어진 게 아닙니다
- AI 모델을 호출하지 않습니다 (그래서 무료이고 빠릅니다)

**그럼 왜 쓰냐면** — 내 업무를 쪼개서 보면, 어디서 막히는지가 눈에 보입니다.
"학습자 분석팀이 자료 대기"라고 떠 있으면, 내가 반응 데이터를 한 번도 안 모았다는 뜻이거든요.

각본은 `src/engine/sim.ts` 맨 위 `SCRIPT` 배열입니다. 단계를 바꾸고 싶으면 거기만 고치세요.

## 7. 자주 막히는 곳

**`npm install` 에서 에러가 나요**
`node -v` 로 확인해서 18 미만이면 새로 설치하세요.

**5180 포트가 이미 쓰이고 있대요**
`npm run dev -- --port 5181`

**직원이 안 움직여요**
위쪽 **"오늘 업무 시작"** 을 눌러야 하루가 시작됩니다.

**부서를 지웠더니 화면이 안 떠요**
3~12개 사이여야 합니다. 화면 위에 뜨는 안내가 무엇이 어긋났는지 알려줍니다.

**글자가 깨져요**
윈도우 기본 한글 글꼴(맑은 고딕)을 씁니다. 맥에서는 알아서 비슷한 글꼴로 바뀝니다.

**`Missing script: "..."` 가 나와요**
받아두신 게 오래된 것입니다. `git pull` 로 당겨 오면 됩니다.
`git pull` 이 `Aborting` 으로 멈췄다면 아직 안 당겨진 것이니,
`git stash` 를 먼저 치고 다시 `git pull` 하세요.
이 교무실은 계속 고쳐지고 있어서, 전에 받은 복사본에는 새 명령이 없습니다.

**`package.json` 을 못 찾는다고 나와요** (`npm error enoent`)
**폴더 밖에서 치신 겁니다.** `cd teacher-office` 로 들어간 뒤 다시 치세요.
검은 창을 새로 열면 늘 집 폴더에서 시작하니, 열 때마다 들어가야 합니다.
지금 어디인지는 창 왼쪽에 적혀 있습니다 — `C:\Users\...\teacher-office` 라고
나와야 맞습니다.

**`'○○' 용어가 인식되지 않습니다` 가 나와요**
**명령어 줄에 설명이 같이 붙어 있으면** 검은 창은 그 설명까지 명령으로 읽습니다.
한 줄에 명령어 하나만 치세요. `<찾을 것>` 같은 꺾쇠도 그대로 치면 안 됩니다 —
그 자리에 실제 내용을 넣으세요.

**`/검수` 를 쳤는데 인식이 안 돼요**
`/` 로 시작하는 것은 **Claude Code 안에서** 치는 것입니다. 검은 창이 아닙니다.
검은 창에 치는 건 `npm run ...` 과 `node scripts/...` 입니다.
